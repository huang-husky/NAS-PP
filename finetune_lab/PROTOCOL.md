# 微调实验协议（v1，2026-11-11 固定）

> **这份文件在跑任何微调之前写好。之后不得悄悄修改；确需修改，写在文末"变更记录"，注明日期和原因。**

## 0. 必须记住的前提

之前 `llm_demo/` 里用的是**冻结的 Pythia / Qwen，平均池化后接随机森林**。这不是已发表工作（RLM、Wu26c、Qin25 等）里的做法，
那些工作的关键是**微调**，而且在输出头、输入写法、分词、预训练数据上都有讲究。
因此：**"冻结 LLM 特征 ≈ 词频"这个结论，只对冻结特征成立，不能推广到"LLM 预测器"。**

## 1. 要回答的问题

在公平的评估协议下，小的开源语言模型经过微调，能不能在 NAS-Bench-201 上，用少量标签（n=100～500）
比"最强的简单基线"预测得更好？哪些因素（输出头、输入写法、初始化、数据技巧）起主要作用？

## 2. 数据与"功能等价"去重

- 数据：NAS-Bench-201，CIFAR-10 精度（`predictor_lab/data/nasbench201.csv`，15625 个结构，`cifar10_acc`）。
- **功能等价**：不在任何"输入 → 输出"连通路径上的边，操作换成什么都不影响网络。
  做法：先找出非 none 的边；从节点 0 能到达、并且能到达节点 3 的边才算有效；其余边的操作视为 none（规范形式）。
  规范形式相同的结构属于同一个"等价类"。15625 个结构共 **9445 个等价类**；同一类内标签的标准差平均 0.21（全体 12.93）。
- **之前 `llm_demo/` 的评估是随机切分，训练和测试里常常有功能等价的结构（泄漏）。** 本协议起，一律按等价类切分。

## 3. 切分（`finetune_lab/protocol.py` 实现）

- 种子 `s`：把 9445 个等价类随机排列。**最后 2000 个类是测试类**（每个类取 1 个代表结构）；**前 n 个类是训练类**（每类取 1 个代表）。
  因此：测试集不随 n 改变；训练集随 n 嵌套（n=100 的训练集包含在 n=200 里）；训练类与测试类没有任何功能等价的结构。
- n 的网格：20、50、100、200、500、1000、2000。
- **评估种子：0～9（基线）；0～4（微调，成本高）。开发种子：100～102，只用来选超参数和调试，评估种子不参与任何选择。**
- 训练标签只用训练代表结构的真实精度。数据增广（等价结构）产生的额外样本沿用该代表的标签，不使用它们自己的真实标签。

## 4. 指标

- 主指标：**Kendall τ-b**（与之前的 `llm_demo` 一致，能处理并列）。
- 辅助：Spearman ρ；regret@10（预测最好的 10 个里，真实最好的精度，与测试集中的真实最高精度之差，越小越好）。

## 5. 基线与"最强简单基线"（包络）

随机森林（200 棵树）配以下特征：one-hot（30）、one-hot+FLOPs+参数量、规范形式 one-hot、规范形式+FLOPs+参数量、
计数+one-hot（35，之前 `llm_demo` 里最好的简单特征）；另有梯度提升（规范形式+FLOPs+参数量）。FLOPs 和参数量由结构分析计算得到（数据文件自带），
属于不需要训练的"免费"特征。

冻结 LLM 对照（沿用之前的特征文件）：Pythia-410M 随机初始化、Pythia-410M 训练完成，随机森林，同一套切分。

**包络**：每个 n，取上面所有简单基线（不含冻结 LLM）10 个种子平均 τ 的最高者。它是微调方案要超过的对手。包络对基线是有利的（挑最大值），所以是保守的。

## 6. 通过线（事先定）

目标区间 n ∈ {100, 200, 500}。某个微调方案"通过"，当且仅当：

1. 在其中至少 2 个 n 上，5 个评估种子的平均 τ 比同一 n 的包络高 **≥ 0.03**；并且
2. 这些 n 上，逐种子配对的差值，至少 4/5 个种子为正。

不通过就如实记录，**不得换指标、换 n、换种子来凑通过**。

## 7. 因子阶梯：一次只改一个因子

每一步只改一处，和上一步比较；每一步都记录。预定的顺序：

| 步 | 改什么 | 取值 |
|---|---|---|
| A0 | 基线微调 | Pythia-70M，普通回归头（均方误差），code 写法，预训练初始化 |
| A1 | 初始化 | 随机初始化（同结构） |
| B | 输出头 | 均方误差（标准化目标）/ 逐位生成数字（交叉熵）/ 成对排序损失 |
| C | 输入写法 | code / 位置词 / 把操作合并成单个词的小词表 |
| D | 数据技巧 | 等价结构增广 / 用 FLOPs 与参数量做"回归预训练" |
| E | 模型 | Pythia-160M、从零训练的小 Transformer、编码器-解码器（T5-small，需下载，放 `finetune_lab/models/`） |

- 超参数（学习率、轮数）只在开发种子上选，选定后固定，再去评估种子上跑。
- **所有试过的配置都要记录，包括失败的；报告时同时报告总共尝试了多少种。** 不得只展示最好的那个。
- 单因子阶梯结束后，对有效的因子做一次**组合验证**（单因子消融发现不了需要同时改两个因子才有效的情况）。

## 8. 已知局限（写在前面）

- 只有 NB201 / CIFAR-10 / 一个搜索空间；结论不自动推广到别的空间或数据集。
- 小模型 + CPU，没有显卡；所有结论限定在小模型上。
- 评估种子之间的差异主要来自"抽到哪些训练结构"，样本少时波动很大。

## 9. 计算预算下的执行方式（在跑任何微调之前补充的澄清）

只有 CPU，一次 Pythia-70M 微调（n=100～500）约需几分钟，不可能每个配置都跑全部评估种子。因此分两层：

- **筛选层（开发种子 100～102，n=200）：** 比较同一因子的不同取值、选超参数。结果只用来决定"哪些配置值得正式评估"，**不作为结论**。
- **评估层（评估种子 0～4，n=100、200、500）：** 只对"记录在案的入围配置"运行，至少包括 A0（基线）、A1（随机初始化）、每一步的最优取值、以及最终配方。
  通过线（第 6 节）只在评估层判定。
- 筛选层试过的**所有**配置（含失败的）都要记录并在报告里给出总数，以便读者判断"从多少种里挑出最好的"。
