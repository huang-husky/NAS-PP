# Demo 结果（NAS-Bench-201 全空间，CPU）

**一句话：** 小样本时，冻结 LLM 特征显著好于手工 one-hot 编码，但这个优势和预训练无关：随机初始化的模型反而最好，代码数据也没有帮助（样本多时，预训练只在 TransNAS 上有帮助）。样本一多，LLM 特征明显落后（天花板低），而且挑最顶尖结构的能力不如 one-hot。解释实验表明，这两点基本都能用"每种操作各用了几次"这 5 个数来解释：把操作随机换边后，LLM 特征在小样本时几乎不受影响。换到 TransNAS-Bench-101（7 个任务）后，同样的现象全部重复出现。在连线方式自由的 NAS-Bench-101 上，"数操作"已经不够用，但只要再数几样代码里看得见的连线信息（一共 6 个数），LLM 特征的小样本优势和天花板同样能被复现。更一般的说法是：平均池化后的 LLM 特征，记住的主要是代码文本里"各种词出现了几次"。换 5 种文本写法的实验进一步表明，LLM 特征的表现基本由写法的词频决定（相关系数 0.88～0.93）；上限来自写法，而不是模型。这个规律在 Pythia 70M、160M、410M、1B 上数值几乎相同，不随模型大小变化；换成另一个模型家族 Qwen2.5-0.5B 也一样。放到模拟搜索里（200 个结构的预算，50 次），这反而是优点：随机 Pythia 特征平均有 68% 的机会找到真正的第一名，one-hot 只有 32%。

（之前用 3000 个结构、10 个种子跑过一个初步版本，在重叠的样本数上结论一致，数字差在 0.05 以内；那版的数据保存在 `results_3000/`。）

## 设置

- 结构池：NAS-Bench-201 全部 15625 个结构；训练集随机抽 n = 10 / 50 / 100 / 500 / 1000 / 2000 个，其余全部当测试集；每种设置 20 个随机种子
- LLM 输入：把结构写成一段 PyTorch 风格代码；取最后一层隐藏状态的平均值作为特征，冻结不训练
- 预测器 = 特征来源 × 回归头：特征来源有 one-hot（30 维手工编码）和 6 个 LLM（Pythia-410M 预训练第 0 / 1000 / 10000 / 143000 步的四个存档，Qwen2.5-0.5B，Qwen2.5-Coder-0.5B）；回归头有岭回归、随机森林、两层 MLP，两两组合
- 目标：CIFAR-10 精度；参数量（合成目标，不可能靠"背答案"）
- 指标：Kendall τ-b（整体排序）、N@10（预测前 10 名里最好的那个真实排第几）
- 显著性：同一批训练划分下的配对 Wilcoxon 检验（20 个种子）
- 运行时间（CPU，Intel Core Ultra 5 125H）：提取特征约 4.7 小时，训练和评估约 2.7 小时

## 发现

下面"x/20"指 20 个种子里前者高于后者的次数，p 来自配对 Wilcoxon 检验。

1. **小样本时 LLM 特征显著更好。** 随机森林下，随机初始化 Pythia 比 one-hot 高：n=10 +0.125（16/20，p<0.001）、n=50 +0.147（20/20，p<0.001）、n=100 +0.079（18/20，p<0.001）。岭回归和 MLP 下，n=10 时也都显著更好。
2. **LLM 特征天花板低，样本一多就明显落后。** 随机森林下，从 n=500 开始 one-hot 反超，而且差距越拉越大：n=500 −0.046、n=1000 −0.086、n=2000 −0.134（都是 0/20 或 1/20，p<0.001）。LLM 特征从 n=500 到 2000 只涨了约 0.04，one-hot 涨了约 0.12。三种回归头都一样。
3. **预训练没有帮助，但有一个例外。**
   - 随机森林下，训练完成的 Pythia 比随机初始化版本差：n=50 −0.025（p=0.017）、n=100 −0.045（p<0.001）、n=500 −0.013（p<0.001）；n=2000 时反过来高 +0.006（p<0.001），但差距很小
   - Qwen-Coder 在随机森林下所有样本数都略差于 Qwen（−0.007～−0.037，p<0.05）
   - **例外：MLP 回归头下，样本多时预训练反而有帮助。** 训练完成的 Pythia 比随机初始化版本高：n=500 +0.082、n=1000 +0.093、n=2000 +0.133（都是 20/20，p<0.001）。原因是随机 Pythia 配 MLP 时几乎不随样本数上涨（n=2000 时只有 0.431）。所以"预训练没用"只在随机森林和岭回归下成立
4. **合成目标（参数量）上，随机模型最好，看不出"背答案"。** 三种回归头下，LLM 特征里都是随机初始化 Pythia 最好，训练完成的版本在所有样本数下都显著更差（例如岭回归 n=10：0.828 对 0.458）。MLP 回归头下，随机 Pythia 在所有样本数都比 one-hot 好；岭回归和随机森林下，n≥500 时 one-hot 追平或略好。
5. **挑"最好的那个结构"，LLM 特征不占优。** 用 N@10 看（随机森林，20 个种子的中位数）：n=100 时 one-hot 是第 3 名，随机 Pythia 是第 21.5 名；n=500 时 one-hot 已是第 1 名，随机 Pythia 是第 10.5 名。LLM 特征整体排序更好，找最顶尖结构的能力却更差，而 NAS 最终关心的是后者。
6. **小样本的随机性主要来自"抽到哪几个训练结构"。** n=10 时各种子间 τ 的标准差，one-hot 是 0.070，随机 Pythia 是 0.143，用全空间也没有变小。要让误差棒变窄，只能多跑种子。

## 为什么少样本好、多样本有上限（解释实验，`explain.py`）

**结论：LLM 特征的表现基本可以用"每种操作各用了几次"（操作计数，5 个数）来解释。** 这个计数是一个很强的简化描述，所以小样本好学；但它分不清"同样的操作放在不同的边上"，所以有上限。

设置：在原来的特征之外，加了两种手工特征：操作计数（5 维）、计数 + one-hot（35 维）。数据集扩到 CIFAR-10 / CIFAR-100 / ImageNet16-120，三种回归头，20 个种子。完整结果见 `results/step1/summary.txt`，图见 `results/step1/fig_counts_vs_llm.png`。

1. **小样本优势：5 个数就能复现，而且更好。** n=10 时，操作计数在三个数据集、三种回归头下都比随机初始化 Pythia 高 0.03～0.08（9 组里 7 组 p<0.05，另外两组 p=0.053 和 0.13）。比 one-hot 高 0.15～0.21。
2. **上限：操作计数有一个算得出来的天花板。** 15625 个结构只有 210 种不同的计数组合。即使知道每组的真实平均精度，τ 最高也只有 0.629 / 0.639 / 0.628（三个数据集）。随机森林下，LLM 特征在 n=2000 时停在 0.63～0.66，只比天花板高一点点；one-hot 则一路涨到 0.77～0.78。
3. **线性探针：随机 Pythia 的特征差不多就是"突出计数的 one-hot"。** 它的特征变化里 75% 能被操作计数线性解释，99.5% 能被 one-hot 线性解释。预训练模型只有约 47%～51% 由计数解释，还有约 25% 是 one-hot 也解释不了的"别的东西"，这些在小样本时更像干扰，所以预训练没有帮助。不过所有模型的特征里，都能以很高准确率读出"每条边放了什么"（平均 96%～100%）：位置信息其实在里面，只是占比小，回归头没用上。
4. **两个例外：**
   - 岭回归（线性回归头）+ ImageNet16 时，LLM 特征在 n=2000 达到 0.68～0.71，超过了计数天花板，也超过 one-hot 的 0.62。原因可能是 LLM 特征相当于对 one-hot 做了一次随机的非线性变换，让线性模型也能用上"操作之间的组合"。但随机森林配 one-hot 能到 0.77，仍然更高。
   - 随机 Pythia 配 MLP 时很弱，样本多了也涨不上去，计数配 MLP 则明显更好。
5. **实用结论：计数 + one-hot（35 维）兼顾两头。** 随机森林下，它在 n≤100 时比 one-hot 高 0.07～0.16，在 n=500 时仍略高，到 n=2000 时只低 0.02～0.03。要拿到 LLM 特征的小样本好处，不需要 LLM，加 5 个计数就够了。
6. **三个数据集规律一致。**

## 检验计数解释：打乱位置、匿名化、分行取特征（`step2.py`）

设置：只看 CIFAR-10，两个 Pythia（随机初始化 / 训练完成），三种回归头。"打乱"是把每个结构的 6 个操作随机换到别的边上（每种操作的个数不变），用打乱后的代码文本提特征，但标签仍是原结构的精度。n≤500 时 20 个种子，n≥1000 时 10 个种子。完整结果见 `results/step2/summary.txt`，图见 `results/step2/fig_nb201_2x2_lines.png`。下面数字都是随机森林。

1. **打乱位置：LLM 特征在小样本时完全不受影响，one-hot 则大跌。** 随机 Pythia 打乱前后 n≤100 时没有显著差别（n=10：0.322 对 0.310），n=2000 时只低 0.04（0.594 对 0.638）。作为对照，one-hot 打乱后在 n=2000 时从 0.772 掉到 0.554（−0.22）。这说明 LLM 特征的小样本优势完全来自计数，样本多时才用上一点点位置信息。
2. **预训练模型比随机模型多用了一些位置信息和名字含义，但没有因此变得更好。** 训练完成的 Pythia 打乱后掉得更多（n≥50 时 −0.04～−0.08）；算子名换成 op_A 这类无意义名字后也变差（−0.04～−0.07）。随机 Pythia 匿名后反而略好（n=10 时 +0.04）。
3. **线性探针印证了上面两点**（`results/step2/probes.txt`）：
   - 打乱文本的特征里读不出原结构每条边放了什么（准确率从 0.96 掉到 0.43，瞎猜是 0.2），而且它能被 one-hot 解释的部分和被计数解释的部分完全一样（都是 75%），说明打乱确实只留下了计数
   - 分行特征里，计数能解释的部分从 75% 降到 36%，每条边的操作读得更准（0.96 → 0.99）：特征不再被计数主导，所以样本多时更好、样本少时更差
   - TransNAS 上的探针结果和 NB201 几乎一样：随机 Pythia 的特征 75% 由计数解释、99.5% 由 one-hot 解释；预训练模型由计数解释的只有 42%～47%
4. **分行取特征能突破计数天花板，但追不上 one-hot。** 随机 Pythia 的分行特征在 n≥500 时比平均特征高 0.04（全部种子都更高），n=2000 时到 0.677，超过天花板 0.629；把打乱文本的分行特征拿来对照，就只有 0.582，仍被卡住。所以突破天花板靠的就是保留下来的位置信息。但它仍比 one-hot 低 0.095，而且 n=10 时比平均特征差 0.07（维度变成 3 倍，小样本更难学）。岭回归和 MLP 下分行特征没有好处。

## 换搜索空间：TransNAS-Bench-101 micro

设置：4096 个结构，和 NB201 是同样的 6 条边，但只有 4 种操作。7 个任务：场景分类、物体分类、拼图、房间布局、语义分割、表面法向、自编码器。标签用 benchmark 的验证集指标。训练集最多抽 1000 个，其余都当测试集。图见 `results/step2/fig_transnas.png`。

1. **小样本时 LLM 好，样本多了被 one-hot 反超，又一次出现。** 随机森林下，n=10 时随机 Pythia 在 7 个任务里有 6 个显著好于 one-hot（+0.10～+0.19，p<0.01）。n=1000 时 7 个任务全部被 one-hot 反超，差距 0.11～0.26。
2. **天花板也对得上。** 只靠计数，7 个任务的天花板是 0.42～0.56。随机 Pythia 配随机森林在 n=1000 时是 0.41～0.59，基本贴着各自的天花板。
3. **计数仍能复现小样本优势。** n=10 时，岭回归下计数在 7 个任务里都不差于随机 Pythia（6 个更高）；随机森林下有 6 个任务两者差别不显著。
4. **反例也符合解释：自编码器任务。** 这个任务的计数天花板最低（0.42），计数最没用。在这里，LLM 特征在小样本时也没有优势（n=10 时比 one-hot 低 0.04～0.05）。计数不管用的地方，LLM 的优势也就跟着消失了。
5. **和 NB201 不一样的一点：样本多时，预训练有帮助。** 随机森林下，训练完成的 Pythia 在 n=10 时和随机初始化版本差不多或略差；但到 n=1000 时，7 个任务全部更好（+0.05～+0.18，都是 p<0.01），自编码器任务上最明显。在 NB201 和 NB101 上，随机森林下预训练都是更差的。可能的原因是：TransNAS 上计数天花板更低，预训练模型特征里那部分"计数以外的东西"（探针显示约占一半）在样本多时开始有用。所以"预训练没用"不能一概而论：小样本时确实没用，样本多时要看搜索空间。
6. **两个和 NB201 一样的次要现象：**
   - 线性回归头下，样本多时 LLM 特征反而好于 one-hot，7 个任务都是这样（n=1000 时 +0.01～+0.16）
   - 计数 + one-hot（随机森林）在 n=10 时比 one-hot 高 0.05～0.12，n=1000 时只低 0.03～0.07

## 换搜索空间：NAS-Bench-101

设置：从 423,624 个结构里按固定种子随机抽 5000 个，标签用 108 轮训练的测试精度（3 次平均）。NB101 每个 cell 有 2～7 个节点、3 种操作，节点之间怎么连都可以，写成代码的方式和 NB201 一样（例如 `x5 = self.conv1x1(x0 + x3 + x4)`，最后 `return torch.cat([x2, x5], dim=1)`）。只用两个 Pythia，训练集最多 1000 个。手工编码：one-hot 是连线 21 位加每个节点的操作 15 位；计数是 3 种操作各用了几次。完整结果见 `results/step2/summary_nb101.txt`，图见 `results/step2/fig_nb101.png`。

1. **这里"数操作"不够用了。** 只靠 3 个操作计数，天花板只有 0.46（全部 42 万个结构上算）。但随机 Pythia 配随机森林在 n=1000 时到了 0.603，远远超过它。
2. **把代码里能"数"出来的连线信息也算上，就又对上了。** 加 3 个数：总连线数、x0 被几个节点用到、输出拼接了几路。这 6 个数的天花板是 0.625（全部结构上算），随机 Pythia 正好贴在下面。把这 6 个数直接当特征（随机森林）：n=10 时比随机 Pythia 高 0.15（20/20），n=100 时仍高 0.05；n≥500 时只低 0.02～0.03。和 NB201 上"计数复现小样本优势、LLM 在样本多时只多拿一点点"的模式一样。
3. **小样本优势比 NB201 弱，反超也来得晚。** 随机森林下，随机 Pythia 比 one-hot 好主要在 n=50～100（+0.10，p<0.001），n=10 时差别不显著；到 n=1000 才被 one-hot 反超（−0.03）。这里训练集最多 1000 个，NB101 结构多、连法复杂，one-hot 需要更多样本才能追上。
4. **预训练仍然没有帮助。** 随机森林下，训练完成的 Pythia 在所有样本数下都比随机初始化的差（−0.05～−0.12）；只有 MLP 回归头、样本多时反过来，和 NB201 一样。
5. **实用结论同样成立：** 计数 + one-hot（随机森林）在所有样本数下都是最好的，n=1000 时 0.668，比 one-hot 高 0.04。

**更一般的解释：** 平均池化把所有 token 的特征平均起来，留下的主要是"各种词各出现了几次"。NB201 的代码里，会变的词只有操作名，所以就等于操作计数；NB101 的代码里，"x0 出现了几次""cat 里有几项"也会变，而且它们和精度关系很大，所以 LLM 特征也就记住了这些。

## 直接检验：词频特征（`make_bow.py`）

上面 NB101 的"连线计数"是看过结果之后挑的，所以这里补了一个事先定好的检验：用 Pythia 自己的分词器把每段代码切成 token，数每种 token 出现了几次（bag-of-words），不挑词、不看精度。所有结构都一样的 token 去掉后，NB201 剩 8 种，TransNAS 剩 6 种，NB101 剩 26 种（包括 `x`、`0`、`+`、`cat` 这类）。然后把它当成一种特征来源，和随机初始化 Pythia 的平均特征比学习曲线（三个空间、三种回归头，设置同上）。

1. **NB201 和 TransNAS 上，词频就是操作计数。** 两者把结构分成完全相同的组（NB201 210 组，TransNAS 84 组），学习曲线也几乎一样（差别都不显著）。
2. **小样本优势：三个空间里，词频都不输给随机 Pythia（随机森林）。** n=10 时：NB201 +0.04（p=0.08）；NB101 +0.04（p=0.015）；TransNAS 7 个任务里 6 个差别不显著，只有语义分割低 0.075（p=0.02）。n=50～100 时，NB201 和 NB101 两者持平或词频略好，TransNAS 上词频略低（−0.01～−0.05）。
3. **样本多时，LLM 特征只比词频多拿一点点（随机森林）。** n 最大时，随机 Pythia 比词频高：NB201 0.02、NB101 0.03、TransNAS 0.01～0.06。和 one-hot 比，这点差距很小（NB201 上 one-hot 比它们高 0.13～0.15）。
4. **回归头不同，结论有两处不一样：**
   - 线性回归头下，样本多时 LLM 特征比词频高很多（TransNAS 上 0.04～0.23）。词频本身是线性的，只靠线性模型用不上"词和词的组合"；LLM 相当于先把词频做了一次非线性混合。随机森林自己就能做组合，所以这点好处就基本没了。
   - MLP 回归头下，几乎所有设置都是词频更好（NB201 上 n≥50 时高 0.13～0.19）。随机 Pythia 的 1024 维特征对没调参的 MLP 很难学。

**结论：** 事先定好的词频特征，复现了 LLM 特征在小样本时的全部优势，也复现了它在样本多时的大部分表现。平均池化的冻结 LLM 特征，基本可以看成"代码文本的词频，再加一层随机的非线性混合"。

## 规律 2：上限由"写法"决定，不由模型决定（`formats.py`、`run_formats.py`、`step3_formats.py`）

设置：同一批结构换 5 种文本写法，分别提取随机初始化和训练完成 Pythia 的平均特征，以及各写法的词频特征。结构池：NB201 随机 5000 个；TransNAS 全部 4096 个，只取场景分类、语义分割、自编码器 3 个任务；NB101 同上 5000 个。回归头用岭回归和随机森林，训练集最多 1000 个。完整结果见 `results/step3/summary.txt`。

| 写法 | 例子（NB201） | 词频里有什么 |
|---|---|---|
| code | `x2 = self.zero(x0) + self.zero(x1)` | 操作计数（NB101 还有连线计数） |
| edges 边列表 | `edge 0->2: zero` | 同上，位置被拆成单独的数字 |
| sorted 只列操作 | `operations: conv1x1 identity zero ...` | 只有操作计数，位置完全删掉 |
| nl 自然语言 | `Node 2 adds zero of node 0 and zero of node 1.` | 同 code |
| posword 位置词 | `cell: tiger piano pencil ...` | 完整的 one-hot（每个"位置 + 操作"一个专门的词） |

1. **LLM 特征的表现基本由写法的词频决定。** 把每个"写法 × 空间 × 任务 × 样本数"组合都画成一个点（横轴词频 τ，纵轴 LLM τ），随机 Pythia 配随机森林时相关系数 r=0.93（125 个点），平均差距 0.037；训练完成的 Pythia r=0.88，Qwen2.5-0.5B r=0.86。岭回归下 r=0.89 / 0.87，平均差距约 0.04，平均偏差接近 0（+0.003 / −0.001）。图见 `results/step3/fig_formats_scatter.png`。
2. **最干净的对照："只列操作"。** 这种写法把位置信息完全删掉，三个空间上、两个模型都和词频几乎一样（随机森林、n=1000：NB201 0.61 对 0.62，TransNAS 0.48 对 0.49，NB101 0.41 对 0.43）。文本里没有的信息，LLM 也变不出来；预训练也没用。
3. **只能数操作的四种写法，天花板都一样。** NB201 上随机森林、n=1000 时 4 种写法的 LLM 特征都在 0.60～0.64，词频是 0.615。换写法本身不改变上限；词序带来的一点位置信息，只让 LLM 比词频多拿 0～0.05（训练完成的模型在 TransNAS 上多一些）。
4. **posword：小样本优势消失，大样本最好，但追不上 one-hot（随机森林）。** 它的词频就等于 one-hot。小样本时 LLM 特征和 one-hot 一样弱（NB201、n=10：0.18，code 写法是 0.38）；样本多时它是所有写法里最高的（TransNAS 0.63），但仍低于 one-hot（0.75）。岭回归下它和 one-hot 没有显著差别（NB201、n=1000：0.478 对 0.500，p=0.28）。
5. **为什么 posword 配随机森林追不上：信息都在，只是被"搅拌"了。** 直接把 NB201 的 one-hot 乘一个随机旋转矩阵，随机森林就从 0.710 掉到 0.563（n=1000），岭回归完全不变（0.496 → 0.495）；随机投影到 1024 维是 0.637。posword 的 0.60 正好落在这个范围里。随机森林只能一个维度一个维度地切分，信息被搅拌到很多维度里就用不好。这也解释了第一阶段的一个现象：LLM 特征配随机森林，样本多时总比 one-hot 配随机森林差一截。

**规律 2 的结论：** 平均池化的冻结 LLM 特征里有什么信息，由文本写法的词频决定；能用上多少，由回归头决定。线性回归头下，LLM 特征 ≈ 词频；随机森林下，被搅拌的信息会再打一个折扣。想突破上限，要改的是写法（让位置信息进到词频里），而不是换模型。

## 规律 3：模型大小不改变规律 2（Pythia 70M / 160M / 410M / 1B）

设置：和规律 2 完全相同（同样的结构池、5 种写法、3 个空间、岭回归和随机森林），只是把 LLM 换成 4 种大小的 Pythia，每种都有随机初始化（第 0 步）和训练完成（第 143000 步）两个版本。完整结果见 `results/step3/summary.txt` 末尾，图见 `results/step3/fig_sizes.png` 和 `results/step3/fig_formats_scatter.png`（每个模型一张子图）。

LLM τ 和词频 τ 的吻合程度（125 个点 = 5 种写法 × 5 个"空间-任务" × 5 种样本数；随机森林）：

| 模型 | 随机初始化：相关系数 / 平均差距 | 训练完成：相关系数 / 平均差距 |
|---|---|---|
| Pythia-70M | 0.929 / 0.036 | 0.861 / 0.054 |
| Pythia-160M | 0.934 / 0.035 | 0.872 / 0.053 |
| Pythia-410M | 0.928 / 0.037 | 0.883 / 0.053 |
| Pythia-1B | 0.935 / 0.035 | 0.875 / 0.051 |
| Qwen2.5-0.5B（另一个模型家族，只有训练完成版） | — | 0.863 / 0.054 |

岭回归下，9 个模型的相关系数都在 0.87～0.90 之间（Qwen 0.867）。

**换一个模型家族也一样。** Qwen2.5-0.5B 和 Pythia 的分词器、训练数据、结构细节都不同，但它的吻合程度和训练完成的 Pythia 几乎相同（0.863 / 0.054），去掉 posword 后相关系数 0.92。也就是说，规律 2 不是 Pythia 特有的。

1. **模型放大 14 倍，"跟着词频走"的程度完全不变。** 随机初始化的模型，4 种大小的相关系数都是 0.93，平均差距都是 0.035～0.037。
2. **具体数字也几乎一样。** 例如"只列操作"写法、随机森林、n=1000，NB201 上 4 种大小是 0.60～0.61（词频 0.615），NB101 上是 0.41～0.43（词频 0.43）；posword 写法 TransNAS 上是 0.63～0.64（one-hot 0.75）。
3. **训练过的模型在每个大小下都比随机的偏离词频多一点**（相关系数 0.86～0.88，平均偏差 −0.02～−0.03，即略差于词频）。预训练给特征加了一些词频以外的东西，但这些东西整体上没有让预测变好；这一点也不随模型大小变化。

**规律 3 的结论：** 从 70M 到 1B，规律 2 的结论在每个大小上都成立，而且数值几乎相同。这为之后用更大的模型验证提供了一个明确的预期：同一张散点图上，点应该还落在对角线附近。

## 规律 4：换层、换取法都去不掉上限（`run_layers.py`、`step5_layers.py`）

设置：code 写法、两个 410M Pythia（随机 / 训练完成），结构池和规律 2 相同。特征取自第 0 层（词嵌入）、第 6、12、18、24 层，每层两种取法：mean（所有 token 取平均）和 last（只取最后一个 token）。岭回归和随机森林，10 个种子（n=1000 时 5 个）。完整结果见 `results/step5/summary.txt`，图见 `results/step5/fig_layers.png`。

1. **第 0 层取平均就是词频。** 三个空间、两种回归头都和词频几乎完全一样（随机森林、n=1000：NB201 0.615 对 0.615，TransNAS 0.486 对 0.486，NB101 0.563 对 0.566）；探针也显示它 99.8% 能被词频线性解释。之后各层在这个基础上做的"混合"，只带来很小的变化。
2. **换哪一层、用哪种取法，天花板都还在。** 随机森林、n=1000 时，第 6～24 层、两种取法在 NB201 上都是 0.61～0.66（词频 0.615，one-hot 0.709），在 TransNAS 上都是 0.52～0.60（one-hot 0.75）。曲线在第 6 层以后基本是平的。
3. **位置信息"读得出来"，但"用不上"。** 线性探针：随机 Pythia 只取最后一个 token 时，每条边放了什么能读出 99%（取平均是 95%～96%）；训练完成的模型在各层都接近 100%。可是预测成绩并没有因此提高。原因是这些特征的变化大部分仍然由计数决定（随机模型 75%～84%），位置信息只占很小一部分，在 1000 个样本以内回归头学不出来。这和第一阶段探针的发现一致。
4. **只取最后一个 token，对训练完成的模型在小样本时明显更差**（NB201、n=10：0.24～0.29，取平均是 0.32～0.40）；对随机模型影响不大。
5. **整体最好的组合是训练完成模型的第 6 层取平均**：NB201 0.663、NB101 0.627（one-hot 0.632）。但在 NB201 和 TransNAS 上仍明显低于 one-hot，没有改变结论。

**规律 4 的结论：** 在不改写法的前提下，换层、换取法都只能带来很小的变化，上限还在。位置信息其实一直在特征里（探针读得出），只是被"计数"这个主要成分淹没了，回归头用不上。结合规律 2，想去掉上限，真正有效的办法是改写法，让位置信息变成主要成分（posword）。

## 规律 5：对"找最好的结构"的影响（`step6_search.py`）

完整结果见 `results/step6/summary.txt`，图见 `results/step6/fig_search.png`。

**A. N@10 也跟着词频走。** 用规律 2 已有的结果（随机森林），把每种"写法 × 空间 × 任务 × 样本数"下 LLM 特征的 N@10 和词频的 N@10 对比（取对数）：随机 Pythia 相关系数 0.89，训练完成的 0.69。

**B. 模拟搜索：小样本优势能直接变成搜索优势。** 设置：先随机测 10 个结构，用测过的结构训练随机森林，预测池子里所有没测过的结构，测预测最好的 10 个，如此循环直到测满 200 个；每种特征 50 次（不同的初始结构），5 个"空间-任务"。

200 个结构以内找到池子里真正第一名的比例（50 次）：

| 特征 | NB201 | NB101 | TransNAS 场景 | TransNAS 分割 | TransNAS 自编码器 | 平均 |
|---|---|---|---|---|---|---|
| 随机搜索 | 0% | 4% | 2% | 4% | 6% | 3% |
| one-hot | 42% | 44% | 28% | 38% | 6% | 32% |
| 计数 + one-hot | 58% | 50% | 44% | 58% | 10% | 44% |
| code 写法词频 | 80% | 58% | 60% | 80% | 24% | 60% |
| **随机 Pythia（code）** | 82% | **66%** | 64% | **86%** | **40%** | **68%** |
| 训练完成 Pythia（code） | 90% | 16% | **80%** | 82% | 30% | 60% |
| Qwen2.5-0.5B（code） | **96%** | 46% | 76% | 76% | 2% | 59% |
| 随机 Pythia（posword） | 66% | 34% | 40% | 56% | 4% | 40% |

1. **用 LLM 特征（code 写法）做搜索，比 one-hot 更容易找到最好的结构。** 同样的初始结构下比最终找到的名次，随机 Pythia 在 5 个任务上都显著好于 one-hot（p 在 2×10⁻⁵～0.003 之间）。50 次里输给 one-hot 的次数：自编码器 11 次，其余任务 4～8 次。（20 次时的结论是"3 个任务显著"，加到 50 次后 5 个都显著，平均比例从 72% 变为 68%，排序不变。）
2. **这个优势同样跟着词频走。** code 写法的词频（不用 LLM）也比 one-hot 好（平均 60% 对 32%）；而 posword 写法的 LLM 特征（词频 = one-hot）就和 one-hot 接近（40%）。搜索时每一轮的训练样本都很少（10～200 个），正好是"数积木"特征占优的范围。
3. **训练过的模型不稳定，Qwen 也一样。** 训练完成的 Pythia 在 TransNAS 场景分类上最好，在 NB101 上明显变差（16%）；Qwen 在 NB201 上最好（96%），在自编码器上几乎找不到第一（2%），NB101 上 46%。随机初始化的 Pythia 是唯一在 5 个任务上都不差的。

**规律 5 的结论：** 在搜索这种"样本少"的实际用法里，"特征 ≈ 词频"反而是优点：词频很快把搜索带到好的那一类结构，所以找到最好结构的机会更大。这和"样本多时有上限"并不矛盾：搜索预算（200 个）还远没到上限起作用的范围。

## 对照检验：COLE 的写法（`step7_cole.py`、`run_cole.py`）

**为什么做：** COLE（Somu 等，GECCO 2026）用冻结的 CodeLlama-7B 读 NB201 代码，N=3516 时 τ=0.797，远高于我们的计数上限 0.63。它的写法给每条边一个名字（`self.op_0_2`），跳连写成 `+ node_1`，无连接直接省略。所以"哪条边放了什么"会改变 `0`、`1`、`2`、`3` 这些词出现的次数，位置信息进到了词频里。按规律 2，这种写法的上限应该更高。

**设置：** 照着 COLE 公开代码（`stringify_utils.py`，'helper' 模式）重写成 `cole` 写法，和论文图 2 一致。结构池、任务和规律 2 相同，提取随机 / 训练完成 Pythia-410M 的平均特征；回归头用岭回归、随机森林、MLP，训练集到 n=2000，20 个种子。完整结果见 `results/step7/summary.txt`。

1. **组内平均上限确实变高了。** 全部结构上，NB201 从 210 组变成 3536 组，上限从 0.63 升到 0.70～0.72（三个数据集）；TransNAS 从 84 组变成 1503 组，7 个任务的上限从 0.42～0.56 升到 0.58～0.67。
2. **但学出来的预测器一点也没变好。** NB201、随机森林、n=2000：

   | 特征 | code 写法 | cole 写法 |
   |---|---|---|
   | 词频 | 0.622 | 0.617 |
   | 随机 Pythia | 0.651 | 0.650 |
   | 训练完成 Pythia | 0.650 | 0.651 |
   | （对照）one-hot | 0.778 | |

   词频离新上限 0.70 还差 0.08。TransNAS 上 cole 写法甚至略差（3 个任务里有 2 个低 0.01～0.03）。岭回归、MLP 下也一样，cole 写法所有组合里最高只有 0.651，比 COLE 报告的 0.797 低 0.15。
3. **原因：位置信息进了词频，但是是"混在一起"进去的。** 比如数字 `2` 出现了几次，同时取决于好几条边。3536 组、每组平均只有 4 个结构，2000 个训练样本根本学不全每组的平均值，所以组内平均上限变成了一个够不着的理论值。posword 不一样：每个"位置 + 操作"有自己专门的词，词频就是干净的 one-hot，所以大样本时能用上。
4. **规律 2 在 cole 写法下仍然成立。** NB201 上 cole 写法的 Pythia 特征和 cole 词频差得很少（n=2000：随机森林 +0.03，岭回归 0.00～+0.04，MLP −0.05～+0.01）。TransNAS 上训练完成的 Pythia 比词频多 0.05～0.22（样本多时、岭回归最明显），但 code 写法下也是这样（规律 2 中已有），和写法无关。

**结论：** COLE 的写法解释不了它的 0.797。用同样的写法，我们的 410M 模型配三种常用回归头只到 0.65，和普通 code 写法一样。剩下可能的原因有三个：
- **回归头：** COLE 先用 PCA 降到 128 维，再用 MLP 加排序损失训练；我们的 MLP 没有调参，在 NB201 上是三种回归头里最差的。
- **模型：** COLE 用的是 7B。但它自己的消融显示模型大小影响很小（1.5B 不比 9B 差，34B 只好一点点），和我们的规律 3 一致。
- **评估方式：** COLE 没写清用的是哪个数据集的精度，用的是 10 折、分层抽样，N=3516 也比我们的 2000 大。

值得注意的是，0.797 和 one-hot 配随机森林的水平（n=2000 时 0.778）差不多，并没有超出"结构信息本身"能给的范围。要分清是回归头还是模型，下一步是在 CPU 上照着 COLE 的回归头（PCA 128 维 + MLP + 成对排序损失）重做一遍，同时用在 cole 词频和 one-hot 上作对照。

**对规律 2 的修正：** "想突破上限就改写法"要说得更准确：位置信息不仅要进到词频里，还要以**单独的词**进去（像 posword）。如果它和别的信息混在同一个词的次数里（像 COLE 的写法），组内平均上限会变高，但学出来的预测器用不上。

## 局限

- 三个搜索空间里，NB101 只抽了 5000 个结构，只用了两个 Pythia，训练集最多 1000 个
- "连线计数"那 3 个数是看过 NB101 的结果之后挑的；事先定好的词频检验（见上）支持同样的结论，但还只用了一种写代码的方式，换一种写法（比如写成邻接表）结论是否不变还没检验
- MLP 回归头没有调参，"MLP 下预训练有帮助"这条可能受超参数影响
- NAS-Bench-201 的 15625 个结构里有不少是同构的（结构等价），这里没有去重
- 和 COLE 的对照只用了 Pythia-410M 和我们自己的回归头；词频用的是 Pythia 的分词器，COLE 用的是 CodeLlama 的
## 建议的下一步

1. 在更大的模型（几 B 到几十 B，需要显卡）上验证规律 2、3
2. 搜索实验加大预算（例如 500～1000 个），看上限什么时候开始拖后腿；以及用"计数 + one-hot"这类不需要 LLM 的特征能否拿到同样的搜索优势
3. NB101 用全部 42 万个结构、更大的训练集（到 n=5000）再验证一次反超点
4. 照着 COLE 的回归头（PCA 128 维 + MLP + 成对排序损失）重做 cole 写法的对照，分清 0.797 来自回归头还是模型
