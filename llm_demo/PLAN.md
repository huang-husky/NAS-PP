# LLM 预测器 demo 计划（NAS-Bench-201，CPU）

目标：一天内拿到一个初步结论，回答"冻结的 LLM 特征在小样本下比手工编码好吗？预训练知识起作用了吗？"。有结果后跟师姐汇报，再看要不要找孙老师申请 GPU。

## 范围（先做小，跑通再扩大）

| 项目 | demo 里怎么做 | 正式实验再扩到 |
|---|---|---|
| 搜索空间 | NAS-Bench-201，只用 CIFAR-10 | 加 TransNAS-Bench-101 等至少 5 个 |
| 结构池 | 随机抽 3000 个结构（测速够快就用全部 15625 个） | 全部 |
| 预测目标 | CIFAR-10 精度；参数量 `params_M`（合成目标，不可能被"背"出来） | 再加 FLOPs、人工构造的目标 |
| 训练样本数 | 10 / 50 / 100 / 500 | 再加 1000 |
| 重复次数 | 10 个随机种子 | 30 个 |
| 指标 | Kendall τ-b、N@10 | 加 Precision@T、统计检验 |

## 比较的预测器

1. **基线**：one-hot 编码 + 随机森林（就是 `predictor_lab/step2` 那个）
2. **Pythia-410M 剂量曲线**：同一个模型在第 0（随机初始化）/ 1000 / 10000 / 143000 步的存档，各自冻结后提取特征 + 小回归头
3. **Qwen2.5-0.5B 对 Qwen2.5-Coder-0.5B**：看多学的代码知识有没有额外帮助

LLM 的输入：把 6 条边的操作写成一小段 PyTorch 风格的代码；取最后一层隐藏状态的平均值作为特征。回归头用岭回归（最简单、几乎不用调参），时间够再试 MLP。

## 明天的步骤

| 步骤 | 内容 | 预计时间 |
|---|---|---|
| 1. 测速 | 每个模型先编码 50 个结构，算出每个结构要多少秒，决定结构池用 3000 还是 15625 | 20 分钟 |
| 2. 冒烟测试 | 训练样本 50、1 个种子，把整条流程跑通，确认没有报错 | 20 分钟 |
| 3. 提取特征 | 6 个模型依次提取，结果存成 `.npy` 缓存，之后不用重复算 | 1–2 小时（后台跑） |
| 4. 训练和评估 | 3 类预测器 × 4 种样本数 × 10 个种子 × 2 个目标 | 约 30 分钟 |
| 5. 画图和整理 | 三张图：τ 随样本数的曲线、Pythia 剂量曲线、Qwen 对 Qwen-Coder | 30 分钟 |

需要下载约 6GB 模型（Pythia 4 个存档各约 0.9GB，Qwen 两个各约 1GB），HuggingFace 可以直接访问。

## 结果怎么读

| 如果看到 | 说明 |
|---|---|
| Pythia 从第 0 步起曲线就很平 | 预训练知识作用小，优势来自模型结构或编码方式 |
| Coder 明显好于基础版 | 代码知识有额外贡献 |
| 精度目标上有优势，参数量目标上没有 | 优势可能来自记忆，而不是理解结构 |
| 所有样本数下都不如随机森林 | 小样本区间 LLM 特征没有优势，转去分析原因 |

## 跑不动时的备选

- 太慢：结构池减到 1000，或把 Pythia-410M 换成 Pythia-160M
- 内存不够：把每批编码的结构数调小
- 下载失败：先只用 Pythia 两个存档（第 0 步和第 143000 步）跑通
