## 严重：会直接影响科学结论
### H1 组均值tau被称为理论上限（已确认）
explain.py:136–141及step2/3/7调用链。均值排序并不优化Kendall tau。实测反例A=[0,1,100]、B=[2,3,4]，均值预测tau=-0.258，交换两组预测则+0.258。应改为组均值oracle参考，或另推导真正上界。它使用全体标签，不是泛化性能估计。
### H2 N@10的oracle被称为最好情况（已确认）
step6_search.py:50。最大组均值并不最大化找到顶尖结构的概率，也不保证最小化N@10。一个组可以包含最高值但均值较低。该函数只能说明特定组均值策略的表现，不能支持所有计数预测器的搜索极限。
### H3 词频等价与位置抹除的机制解释过强（已确认）
run_layers.py:7–8。第0层mean是按长度归一化的token嵌入和，不是原始计数直接乘矩阵；即使是可逆线性变换，随机森林也不保证性能相同。后续层的token已包含上下文，平均不保证消除顺序信息。formats.py“前四种只有操作计数”对NB101不成立：code/edges/nl/sorted在当前池分别1749/3416/2336/44组。
### H4 第四页参考线定义/总体混用（已确认）
make_summary_fig.py:19–22。NB101用42万总体纯计数0.462对5000子集的词频/LLM曲线。0.625也是不同特征定义的经验值，不能为贴线而替换。TransNAS0.509数值可复算，不意味着是LLM上界。

## 重要：指标和实现缺陷
### M1 并列精度被强制分成不同名次（已确认存在当前数据）
evaluate.py:76、step6_search.py:53/115，双argsort给相同标签不同名次。TransNAS autoencoder当前池有两个并列最优结构，代码只有一个rank=1，故“找到第一比例”实际是找到任意指定的唯一结构。建议采用并列最小名次，并用best_value==max(y)判断找到最优；预测并列按固定随机种子打破，报告策略。
### M2 搜索预算与缓存不匹配（局部复现）
step6_search.py:118–139。budget=15实际评估20，budget=5实际评估10；预算大于池还可能失败。done只按space/target/features/run识别，先跑40再改200会跳过旧运行。建议batch=min(step,budget-tested,remaining)，校验参数，缓存包含预算和配置并验证完整性。当前2000条运行均到200，未发现当前受此缺陷影响。
### M3 缓存无输入指纹且写入非原子（风险可由代码触发，当前未证实污染）
run_formats.py:73/88，embed.py:183，step3_formats.py:101/129，step2.py:164/206。仅存在即跳过，文本、数据顺序、权重或依赖改变后可能沿用旧结果；drop_duplicates默认保留旧行。--limit与正式目录混用也可能写入短数组。建议输入清单+哈希+配置版本，写临时文件后替换，完成标记校验尺寸与有限值。当前250份数组没有短文件/非有限值。
### M4 总相关系数与平均偏差掩盖异质性（已复算）
step3_formats.py:132–151。混合样本数/任务/格式，总r随机Pythia/训练Pythia/Qwen=0.928/0.883/0.863，n=1000时=0.830/0.653/0.540。MAE=0.037/0.053/0.054，不能统一说0.04。125点中75点是TransNAS，非空间等权；同数据重复点不独立。建议分层、配对差值与置信区间，区分相关与一致。
### M5 大量配对显著性没有多重比较控制（方法学限制）
explain.paired、step2.paired_common、step6.run_search重复Wilcoxon。建议预先指定主要比较，并报告效应大小、区间以及适当的多重比较校正；不能把每个未经校正的小p都当作独立强证据。
### M6 警告被隐藏、未定义tau被变成0（已确认）
explain.py:88–91、evaluate.py:112–117。常量预测导致NaN记0有解释空间，但必须与失败分开；不收敛及其他警告全隐藏会让失败看起来像有效结果。建议保留状态、收敛告警和原始tau。
### M7 数据构建缺少来源与稳定ID约束（风险）
build_nb101.py QUERY无ORDER BY，后续pool只存行下标；重新导出时顺序改变可能让旧特征与标签错配。build_transnas.py发现unfinished仅计数仍写入；build_dataset.py以最好值相近推断验证/测试含义不够，轴顺序也应绑定原始元数据。当前CSV无缺失，但不能由此证明原始来源语义完全正确。建议按结构hash/arch_str持久化映射，保存元数据与原始校验和。
### M8 跨模型词频基线需准确命名（已确认）
run_formats使用Pythia tokenizer构造所有bow，包括比较Qwen时。作为共同基线可以成立，但不能解释为Qwen自己看到的token计数。需补模型自身分词器基线或限定表述。

## 一般问题及改进
- explain.variance_explained在全数据拟合并评分，是样本内描述性R²；不要与probe的留出集读出分数混称泛化指标。
- explain.paired只按排序后数组长度检查配对；相同数量但不同seed会错配。step2.paired_common按seed交集更稳健，应统一。
- 学习曲线无种子误差带，主图硬编码常数且未校验任务/种子完整性；第六页图例的颜色/形状双编码混在一起，灰色不是缺失数据。
- models.has_weights只看文件名和大小，不能保证完整性；Qwen revision=main未固定commit；下载后删除缓存元数据损失可追溯信息。
- run_overnight.sh不检查每步返回码，失败仍能打印“全部完成 EXIT”；等待旧日志EXIT可能误判。Python调度版本做得更好。
- predictor_lab/checks.check_split未检查内部重复/越界/全集覆盖；check_tau对NaN比较可能放行；MLP y标准差为0或无有效排序对时缺少保护。教学默认数据未证实触发。
- predictor_lab教学脚本和download_models.py有导入即执行副作用；生产实验应使用main入口。
- step5/step7通过修改step3模块全局变量复用逻辑，单进程顺序脚本可用，但导入顺序/扩展时容易隐性串配置。
- 数据导出精度四舍五入会增加并列；可保留原始精度并只在显示时舍入。
- 缺少统一依赖锁定和自动化测试入口，已有checks主要面向教学，未覆盖正式流水线的缓存、预算和指标边界。
