# 研究思路讨论记录（11月9日）

Nov 9, 2026

## 当前结论

**今天的讨论把研究从“诊断 LLM 编码在做什么”推进到“LLM 读不懂结构、需要显式结构建模”，但还缺最关键的一环：GNN 已能处理架构，为什么还需要 LLM。** 按现有数据，只输入架构时 LLM 没有独有贡献，所以动机暂不能定稿。

- **方向：** 继续 NAS 性能预测 + LLM（孙老师给的方向），不做调研型工作；方向 2（agent + RAG）暂缓。
- **候选回答：** 让 GNN 负责架构连接，LLM 负责任务与背景信息（任务描述、数据集），检验它能否更快适应没见过的任务。现有基准（TransNAS-Bench-101 的 7 个任务、NB201 的 3 个数据集）就能做，不需要新数据。
- **定稿前必须先确认两件事：** 结构不足是否真的造成排序或选择损失；LLM 是否提供了 GNN 没有的收益。
- **做法：** 先用 ≤1.5B 开源模型跑两个小实验，有支撑结果后再向老师申请 32B 资源。
- **旧文档：** [第二页动机重写](https://claude.ai/artifact/P95CU3z3oUrzeLLkoCqDct)基于旧框架，只作文献参考，不再沿用其中的问题设定。

## 老师与师姐意见要点

**孙老师（三轮 PPT 批注）**

- 引用起点要高：至少 CCF-B，最好 CCF-A；高水平论文的已有研究更深入，在此基础上做才好。
- 要先分析领域现状和大家真正关心的问题，判断问题是否存在、是否亟需解决；不能“没人做就要做”。
- 若重点是“用不用 LLM 提特征的差别”，全文就要回答 LLM 比非 LLM（主流是 GNN）多贡献多少；参照 White 等 NeurIPS 2020（编码研究）和 NeurIPS 2021（How Powerful）。
- 术语统一：第一点就要引出 encoding；“LLM-based encoding”“backbone”等说法要准确。
- 对照要有理由：为什么比这两个？影响 LLM 效果的还有哪些因素？
- 必要性说不清，审稿人就不会往下看。

**师姐（NAS + 机器学习方向）**

- 孙老师可能不希望做调研型工作；这个方向相关研究少、无共识，LLM 结果普遍不好，在此基础上比较价值不大。
- NAS + 性能预测器已较成熟，LLM 很火，NAS 性能预测 + LLM 是老师给的方向。
- 顶会顶刊多用 GPT 等闭源模型，开源小模型效果差；先在小模型上做出能支撑观点的结果，再向老师申请资源（实验室支持 32B 模型的高效训练）。
- 她的经验：LLM 在文本上好、在架构上不如传统机器学习；这类问题其他领域也有，可看他们如何处理“LLM 真正理解结构还是只用 token 统计”。
- LLM 的优势：使用门槛低，不需要机器学习背景；除了一个数字，还能输出概述（如各数据集上的精度和平均值）。
- 备选方向 2：搭建带记忆与经验的 agent 系统（多个 RAG），暂缓。

**对师姐建议的两点修正**

- 开源模型反而是必需的：结构注入、软 token、投影器都要接触模型内部，闭源 API 做不到。
- “审稿人多是外行”不能写进动机；生成的说明还必须与预测一致，否则会被质疑是幻觉。

## 关键缺口：为什么需要 LLM

**只证明“LLM 缺结构、GNN 能补”不够，还要证明“补完之后 LLM 提供的那部分值得保留”。** 否则最多说明给 LLM 补结构有用，不能说明它对 NAS 性能预测有价值。

动机链五句的修改意见：

| 原论述 | 修改 |
| --- | --- |
| NAS 性能预测已经成熟（GNN 编码器） | 改为“已有以 GNN 等为代表的性能预测方法”；“成熟”推不出需要 LLM |
| LLM 能提供统一的文本接口 | 必须说明统一哪些输入、解决什么困难；只把架构图写成文本，并不比直接输入 GNN 更有价值 |
| LLM 读结构差，多领域有证据，NAS 上也测到了 | 收窄为“我们考察的文本模型在某类结构区分上存在不足”；其他领域只提供线索，具体结论要靠 NAS 实验 |
| 其他领域用结构注入解决了这个问题 | 改为“显式结构建模在其他任务中取得改善，为我们提供方法依据”；迁移已有方法本身不算足够的创新 |
| 架构是 DAG，天然适合这种做法 | 只说明可行性，不说明必要性；限定为“所研究的搜索空间可表示为 DAG” |

文本接口有没有用，取决于任务设定：

- **只输入架构、预测固定数据集上的性能：** 文本接口优势弱，GNN 已能直接处理图，需要实验证明 LLM 有额外收益。
- **需要联合处理架构与数据集描述、训练配置或任务约束：** 文本才有具体用途——承载不同类型的信息，图编码负责连接关系。但需要对应的数据和实验，不能只为动机加入。

另外，**“统一接口”与“跨搜索空间泛化”要分开**：格式统一不等于预测规律能迁移；若主打跨空间，必须实际测迁移。

## 现有数据对两个关键事实的回答

**标签多时结构不足确实造成排序损失；但只输入架构时，目前没有证据表明 LLM 有独有贡献。** 数字均来自第五版 PPT 的实验（冻结特征，Pythia 70M–1B、Qwen2.5-0.5B）。

| 关键事实 | 已有证据 | 初步结论 |
| --- | --- | --- |
| 1. 结构不足是否造成排序或选择损失 | NB201 RF n=2000：one-hot 0.772，LLM 特征约 0.64。TransNAS RF n=1000：one-hot 0.717，LLM 0.52–0.55。搜索：预训练 Pythia 在 NB101 上找到最优架构的比例 16%，随机初始化 Pythia 66%。但 n≤100 时及搜索的其余 4 个任务上，LLM 特征优于 one-hot | 标签多时有明确排序损失；标签少时没有。结论要限定预算 |
| 2. LLM 是否提供 GNN 没有的收益 | 冻结 LLM 特征与 token 计数的相关 r≈0.82–0.92。搜索：随机 Pythia 67.6%，token 计数 60.8%，5 个任务中只在 1 个上显著。预训练相对随机初始化无稳定收益。GNN 基线尚未运行 | 只输入架构时没有证据；LLM 的优势基本能被 token 计数复现 |

含义：如果论文停留在“只输入架构、固定数据集”，按现有证据很可能答不出“为什么需要 LLM”；继续加结构模块，最好也只是让 LLM 追上 GNN，而“追上”不构成需要它的理由。

## 候选方向：GNN 负责结构，LLM 负责任务信息

**让两者各做擅长的事：GNN 编码架构连接，LLM 编码任务和数据集的文字描述，检验它能否更快适应没见过的任务。** GNN 加任务 one-hot 对未见任务无能为力，文字描述则可能借上 LLM 的先验知识——这是 GNN 本身答不了的问题。

**数据现成：**

- TransNAS-Bench-101：同一批 4096 个架构有 7 个任务的标签（分类、分割、自编码等），任务差别大，可写出有意义的描述。
- NAS-Bench-201：同一批架构有 CIFAR-10、CIFAR-100、ImageNet16-120 三个数据集的标签。
- 可能的扩充：ONNX-Bench 中 einspace 上的 8 个 Unseen NAS 数据集（标签是否公开待确认）。

**其他领域的方法依据**（只提供线索，NAS 上的结论靠我们自己的实验）：

- NLGraph（NeurIPS 2023）：LLM 在复杂图结构上失败并依赖伪相关；连通性任务换成链状图后平均准确率从 78.4% 降到 54.8%。
- Talk like a Graph（ICLR 2024）：只换图的文本写法，准确率相差近 50 个百分点。
- LLaGA（ICML 2024）：冻结 LLM，只训练投影器把图结构映射进 token 空间，多数设定下优于 GNN。
- GraphToken（arXiv 2024）：GNN 生成软 token 接到冻结 LLM 前，节点计数任务 99.6% 对最好基线 27.6%。

**动机链草稿**（方括号内需要实验填上）：

> **实际需求：** 搜索新任务时，标签很少，需要利用任务本身的信息加快预测器适应。 **采用 LLM 的理由：** LLM 能读任务和数据集的文字描述，提供 GNN 加任务编号无法提供的先验。 **已观察的瓶颈：** 直接读架构文本时，LLM 特征与 token 计数高度相关（r≈0.82–0.92），标签多时排序明显低于 one-hot。 **方法假设：** 由 GNN 编码架构、LLM 编码任务描述，二者结合可兼顾结构与任务先验。 **价值验证：** 在相同标签与计算预算下，对未见任务［在 0、10、50 个标签时］同时优于纯文本 LLM 和 GNN（含任务编号），并改善架构选择。

## 风险与放弃条件

**事先写下放弃条件，避免再次为结果找理由。**

| 风险 | 说明 | 放弃或转向的条件 |
| --- | --- | --- |
| 任务太少 | 留一任务法只有 7 + 3 个任务，泛化结论偏弱 | 若 Unseen NAS 等数据不可用，结论只能限定在这两个基准 |
| 已有相近工作 | MetaD2A（ICLR 2021）用数据集样本条件化地生成和预测架构；HELP（NeurIPS 2021）用硬件嵌入迁移；NAS 中 TG-NAS、LeDG-Former 已把文本特征喂给图模型。尚未系统检索 | 若已有工作用文字描述做任务条件化预测，需重新定位贡献 |
| 收益为零 | 任务描述的收益可能不比一个可学习的任务嵌入多 | 小实验中 LLM 任务描述不优于任务 one-hot 或可学习嵌入时，放弃该方向，不再另找理由 |
| 小模型不足 | ≤1.5B 模型可能读不懂任务描述 | 小模型无收益但有趋势时，再申请 32B 验证；无趋势则不申请 |
| 范围扩大 | 引入任务信息会扩大研究范围 | 只用现有基准中已有的任务和数据集，不为动机新造设定 |

## 下一步

**先查文献确认空白，再跑两个小实验，结果出来后才写第二页。**

- [ ] **文献检索：任务条件化的性能预测器。** 确认 MetaD2A、HELP 等已有工作的设定；查有没有人用文字描述做任务条件化预测，或在 NAS 上把图结构注入 LLM。
- [ ] **小实验 1：补 GNN 基线（只输入架构）。** 在 NB201 和 TransNAS 上用现有划分和预算（n=10–2000）跑 NN-Former（CVPR 2025，代码公开）或 TA-GATES（NeurIPS 2022），正式回答“只输入架构时 LLM 有没有独有贡献”。预期答案是没有，这一页作为转向任务信息的依据。
- [ ] **小实验 2：留一任务（加入任务信息）。** 在 TransNAS 的 7 个任务上，对未见任务给 0、10、50 个标签，比较：GNN、GNN + 任务 one-hot、GNN + 可学习任务嵌入、GNN + LLM 编码的任务描述、纯文本 LLM。用 ≤1.5B 开源模型（如 Qwen2.5-0.5B/1.5B）。
- [ ] **结果评估。** 小实验 2 中“GNN + LLM 任务描述”明显优于其余设置，才写动机并申请 32B 资源；否则按放弃条件处理。
- [ ] **与老师确认。** 小实验结果出来后，先用一段话向老师说明方向，再做 PPT。

暂缓：方向 2（agent + 多个 RAG 记忆系统），方向 1 走不通时再考虑。
