# 研究设定核对与下一步判断

2026-11-16。依据原论文方法、实验章节和作者代码完成的第一轮核对。详细方法核对主要使用明确标出的公开预印本版本。

## 需要更正的判断

此前把 RLM 概括为“关键是微调”，据此推断冻结特征偏离已有工作，这个说法过于笼统。RLM 正式论文摘要明确写使用冻结 LLM 编码器。2025 年预印本第 6.1 节也比较语言预训练、随机初始化和冻结编码器。冻结与否只是一个训练配置。

我们做过的冻结平均池化加 RF，与 RLM 的编码器—解码器数字生成、多任务回归训练、ONNX 输入存在多方面差异。小 Pythia 的固定步数排序微调也没有复现 RLM。既有失败结果只能约束对应实现与预算，不能据此否定已有 LLM 性能预测路线。

来源：[RLM 正式摘要](https://proceedings.mlr.press/v306/akhauri26b.html)、[RLM v1 第 3、4、6 节](https://arxiv.org/html/2509.26476v1)。

## 这一轮能做的方向判断

保留 NAS 性能预测与 LLM 的研究范围。当前最值得深入核对的候选问题是：在目标空间标注很少、可用历史架构数据有限时，怎样降低语言预测器的任务训练数据需求，同时保持跨空间的架构选择能力。

依据是 RLM 使用专门回归预训练，LM-Searcher 构造大量轨迹，其局限章节明确指出对已有架构—性能数据的可用性和质量存在依赖。这给出数据成本的现实切入点。但“减少训练数据”是否已被其他方法解决，以及哪种数据最有价值，尚需查新和复现验证。

必须分别记录独立的已评估架构数、由这些架构组合成的训练样本数、训练计算量及目标空间新增评估数。228K 条轨迹不等于训练了 228K 个独立架构；也不能将旧数据可直接复用的成本按本轮重新训练全部架构计算。

## 开始新方法实验前要交付的证据

1. 在 LM-Searcher 与 RLM 中选一条有可用代码、模型和数据的路线，核对源与目标空间分割、是否使用目标标签、表示细节、超参数及模型选择方式。
2. 把官方方法、相同资源条件下的强图预测器和现有便宜结构基线放到相同评估协议。先能解释复现与论文差异，再谈改进。
3. 用可用数据量的受控变化确认训练数据是否真的限制迁移，最终指标采用达到同等架构选择质量所需的目标评估数，并计入预测器训练与推理时间。
4. 若差距主要来自实现或训练不足，优先修复。若官方方法在目标预算下已足够好，重新选择问题。只有确认数据限制和可改善幅度后，再考虑数据选择、轨迹构造或其他方法。

下一项工作是查官方复现资源并形成上述成本与协议表。当前尚未证实一个可宣称新颖的方法，也未得到正式方法的失败证据。
