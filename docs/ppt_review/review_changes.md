## 一、优先处理的实质性问题

### 1. 绿色水平线不是 LLM 上限（严重）

涉及主4、5、6、7、9、10，附9、11、12、13、17、21及相应备注。

代码做的是：按操作计数分组，把每个结构预测为该组真实标签的均值，再计算预测与真实标签的 Kendall τ-b。NB201 CIFAR-10 的值约 0.629。

- 它是使用整组真实标签的描述性 oracle 参考值，不能作为训练所得模型的公平测试成绩。
- 组均值最小化组内平方误差，不保证最大化 Kendall 排序相关，因此也不是“只知道计数时的最佳排序”。
- LLM 输入包含顺序、边位置等信息，其特征也已被探针读出位置信息。不能假定 LLM 等价于计数向量。
- 有限样本曲线接近该值不能证明渐近收敛到它；图中的 TransNAS、NB101 曲线也超过了原绿线。

拟修改：删除 ceiling、at most、capped、无上限、理论上限等结论。建议主4展示真正训练的操作计数基线曲线，组均值水平线移到附件作为诊断参考；若保留水平线，必须在图例和正文明确“组均值参考，非 LLM 上限”。不能通过移动水平线使其贴合 LLM 曲线。

### 2. 第六页不是丢图，而是图例设计造成误读（明确）

红色表示 posword，方块表示 TransNAS，所以红色方块是有效数据点；灰色圆、方、三角仅在图例示意空间的形状编码，不应期待图内出现一组灰色数据。

拟修改：将图例分为“颜色＝文本格式”“形状＝搜索空间”，补充点大小含义或取消大小编码；拆分拥挤图例。不要删除红色方块或补造灰色点。

### 3. 分层图把未定义 τ 画成了 0（严重）

主7、附15仍使用旧图。常量预测时 τ 不可定义，不能画成有效零值再连线。已修正结果里共有728条此类记录，包含720条常量特征记录及8条定向重跑确认的记录。

拟修改：用修正图替换，未定义点留空并标注原因、有效种子数；不将“层0到层6从0跃升”解释成信息突然出现。

### 4. 搜索表使用旧并列名次（严重，但并非所有结论失效）

主8、附16、22、23。旧双重 argsort 给并列真实标签分配不同名次，导致找到并列最佳结构也可能被算失败。

主8 TransNAS autoencoder 列应更新如下：

| 特征 | 原值 | 修正值 |
|---|---:|---:|
| Random search | 6% | 12% |
| one-hot | 6% | 8% |
| Counts + one-hot | 10% | 10% |
| Token counts | 24% | 26% |
| Random Pythia | 40% | 40% |
| Trained Pythia | 30% | 34% |
| Qwen | 2% | 4% |

五列任务成功率的算术均值依次为4.4%、32.0%、44.0%、60.8%、67.6%、60.4%、59.6%。建议统一保留一位小数，并写明按五个任务平均，不是按三个空间平均。

本次用修正后的最终 best_rank、按 run 配对重新计算双侧 Wilcoxon：NB201 p=0.00002080、NB101 p=0.003025、scene p=0.0005225、segment p=0.002462、autoencoder p=0.002427。若检验族限定为这5项随机 Pythia 对 one-hot 比较，Bonferroni 后均小于0.05。因此可以保留“这五项最终名次比较显著”，但不能说这是对成功率比例做的检验，也不能把此校正范围推广到全部实验。

修正结果保留历史选择轨迹；不能写成已经使用新预测并列策略重新跑了50轮搜索。

### 5. COLE 对照没有条件支持因果归因（严重）

主9、12、附4、17、18。原文0.797对应 n=3516、CodeLlama Python 7B、10折×10种子分层抽样，并使用 PCA128、MLP及排序损失。这里的主要对照是 n=2000、Pythia410M、不同数据池和划分。因此不能由两者差异认定“高分不来自格式”“最可能来自回归头”，也不能说0.797与one-hot的0.778已证明同等水平。

拟修改：“在本地 Pythia410M + RF 设置下，仅替换为 COLE 风格文本未观察到明显改善；尚未完成 COLE 全流程同协议复现。”头部、模型、样本量、标签字段和划分都是待控制因素。原文配置见 [COLE论文第4.1节及表1、3](https://arxiv.org/html/2605.15649v1)。
